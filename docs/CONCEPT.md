# MIXNAVUTS — 전체 시스템 구상

Predictive Multi-Route Navigation. 수백 개의 후보 경로를 탐색하는 엔진에 차량 인포테인먼트와 랠리 스타일 HUD를 결합한다.

## 핵심 원칙

1. 수백 개의 경로를 탐색하는 능력보다, 그중 **어떤 경로가 실제로 가장 빨리 도착하는지 정확하게 판단하는 능력**이 더 중요하다.
2. 후보는 내부적으로 폭넓게 검토하고, 사용자에게는 좋은 경로 3~5개만 제시한다.
3. 최적화 목표는 후보의 개수가 아니다. 좋은 경로를 놓치지 않으면서 빠르게 계산하는 것이다.
4. 고속도로가 무조건 빠른 것도, 국도가 무조건 느린 것도 아니다. 모든 대안을 **목적지 예상 도착 시각**으로 비교한다.
5. 엔진의 ETA 정확도를 먼저 검증하고, 차량 화면과 HUD는 그다음에 붙인다.

## 시스템 구성

```
입력                                    엔진                               출력
실시간 교통 (속도·정체·사고·통제)  ┐
고속도로 정보 (IC·JC·통행료·정체)  ├─▶ 후보 경로 생성 (수백 개)        ┌─▶ 스마트폰
미래 교통 예측 (시간대·유입·정체)  │    ▶ 시간 의존 ETA 시뮬레이션   ├─▶ 차량 화면 (Android Auto·CarPlay)
개인화 (평소 경로·주행 목적)       ┘    ▶ 선호·다양성 기반 3~5개 선택 └─▶ HUD
```

| 모듈 | 기능 | 현재 구현 |
| --- | --- | --- |
| MIXNAVUTS Route | 수백 개 후보 경로 생성 | `mixnavuts/candidates.py`, `search.py`, `evaluate.py` |
| MIXNAVUTS Traffic | 실시간·미래 교통 상황 예측 | `mixnavuts/traffic.py`, `live.py`, `korea/its.py`, `korea/archive.py` |
| MIXNAVUTS Distribution | 다수 차량의 경로 분배 최적화 | 미구현 |
| MIXNAVUTS Personal | 운전자 선호와 주행 목적 분석 | `mixnavuts/ranking.py` (주행 목적별 비용만) |
| MIXNAVUTS Navigation | 위치 추적·차선 안내·재탐색 | `mixnavuts/guidance.py`, `roadinfo.py`, `korea/hdmap.py`(정밀도로지도 차로) + 앱 코어의 `RouteTracker`·`NavigationSession` |
| MIXNAVUTS Connect | Android Auto·CarPlay 연동 | `android/app/.../car`, `ios/Mixnavuts/CarPlay` |
| MIXNAVUTS HUD | 속도·도로 형상·분기점·ETA 표시 | 앱 코어의 `HudState` (속도, 차로, 단속카메라·과속방지턱 경고, 페이스노트). 화면 디자인은 미정 |
| 자체 지도 | 지도 타일·검색 | `mixnavuts/tiles.py`, `mapstyle.py`, `korea/vworld.py`, `korea/juso.py` + 앱의 MapLibre |

제품은 두 가지로 나눌 수 있다.

- **MIXNAVUTS Engine**: 경로 탐색·교통 예측·분배 엔진. 외부 서비스에도 제공할 수 있는 형태.
- **MIXNAVUTS App**: 스마트폰, Android Auto, CarPlay, 지원 차량 HUD를 활용하는 사용자용 내비게이션.

## 경로 탐색: 계층형 다중 후보

1. 도로망에서 최단시간·최단거리 등 기본 경로를 계산한다.
2. 다른 고속도로, IC, 간선도로를 쓰는 대안 경로를 만든다.
3. 지나치게 겹치는 경로를 정리하고 후보군을 넓힌다.
4. 수백 개의 유효 후보마다 예상 통행시간을 계산한다.
5. 교통 예측을 적용해 최종 3~5개 경로를 제시한다.

프로토타입에서 1은 비용 프로파일, 2는 페널티 방식, 3은 via-node 방식으로 구현했다. via-node 방식은 순방향·역방향 탐색 두 번으로 노드마다 하나씩 후보를 얻으므로, 후보 수가 늘어도 탐색 비용은 거의 늘지 않는다.

### 프로토타입의 알려진 한계

- **교차로 회전 비용이 없다.** 도심에서는 좌회전 신호 대기가 ETA 오차의 큰 원인이다. 링크 기반(edge-based) 그래프와 회전 제한·비용이 필요하다.
- **통행료를 링크별로 근사한다.** 한국 고속도로 대부분은 폐쇄식이라 요금이 진입·진출 영업소 쌍으로 정해진다. 영업소 간 요금표로 계산해야 한다.
- **via 경로의 국소 최적성을 검사하지 않는다.** 불필요하게 돌아가는 후보가 섞일 수 있다. 지금은 ETA 평가와 겹침 필터가 걸러낸다. 개선하려면 plateau나 T-test 같은 방법을 쓴다.
- **관측되지 않은 링크는 평소 패턴만 쓴다.** 인접 링크의 정체를 전파하는 공간 모델이 없다.
- **요일·공휴일·날씨 구분 없이** 하루 프로파일 하나만 쓴다.
- **ETA가 점 추정이다.** 실제 서비스에서는 P50/P90 같은 분포로 신뢰도를 함께 보여 주고, 늦을 위험이 적은 경로를 선호할 수 있어야 한다.
- 도로망 규모가 커지면 Contraction Hierarchies나 CRP 같은 전처리 기반 가속이 필요하다.

## 교통·고속도로 데이터

| 정보 | 경로 계산에 반영할 내용 |
| --- | --- |
| IC·JC | 진입·진출과 분기 경로 |
| 정체 상황 | 구간별 예상 통과 시간 |
| 통행료 | 예상 비용과 무료 경로 비교 |
| 사고·공사 | 차로 폐쇄, 통행 불가 구간 |
| 시간대별 정체 | 실제 진입 예정 시각의 교통 예측 |
| 휴게소 | 장거리 경로의 경유지 |
| 차로별 정보 | 분기점·출구 안내 정확도 향상 |

후보 데이터 소스. 제공 항목, 갱신 주기, 이용 조건은 연동 전에 각 기관 문서로 확인해야 한다.

- **국가교통정보센터(ITS)**: 교통소통정보, 돌발상황, 교통예측, 가변형 제한속도 등.
- **국가표준노드링크**: ITS 소통정보가 쓰는 링크 체계. 엔진 도로망을 이 체계에 맞추거나 OSM과 매칭해야 실시간 속도를 붙일 수 있다.
- **한국도로공사 공공데이터**: 고속도로 통행료, 휴게소, 구간 소통 정보 등.
- **OpenStreetMap**: 도로 형상, 회전 제한, 굴곡도 계산용 형상.

### 지금 바로 해야 할 일: 데이터 아카이브

ETA 백테스트에는 과거 링크 속도가 필요하다. 아카이브가 있으면 출발 시점까지의 데이터만으로 예측하고, 이후 데이터를 재생해 실제 통행시간과 비교할 수 있다. 직접 주행하지 않아도 정확도를 검증할 수 있다는 뜻이다. 그러려면 수집을 일찍 시작할수록 좋다. 요일·계절별 패턴과 드문 돌발상황까지 담으려면 몇 달 치가 쌓여야 한다.

## 차량 화면과 HUD

| 플랫폼 | 구현 가능한 영역 | 제약 |
| --- | --- | --- |
| Android Auto | 지도, 안내, ETA, 속도 표시, 계기판 연동 | 차량과 지원 API에 따라 다름 |
| Apple CarPlay | 자체 지도, 턴바이턴 안내, 계기판·HUD 안내 | Apple 내비게이션 권한과 차량 지원 필요 |
| 자동차 순정 HUD | 다음 회전·거리·진행 방향 등 | 제조사·차종별 표시 기능에 종속 |
| 독립형 HUD | 전용 디스플레이에 맞춘 커스텀 인터페이스 | 별도 하드웨어와 연동 프로그램 필요 |

- Android for Cars App Library에서는 `NavigationManager.updateTrip()`으로 경로 정보를 차량 계기판·HUD에 전달한다.
- CarPlay 앱은 템플릿 기반이라, 모든 차량 HUD에 임의의 그래픽을 그대로 출력할 수는 없다.
- 랠리 스타일의 완전한 커스텀 HUD는 스마트폰 화면이나 전용 디스플레이에서 먼저 구현하는 것이 현실적이다.
- 속도는 지원 차량의 속도 센서(Android 차량 API)나 스마트폰 GNSS(iOS Core Location의 속도·정확도)로 얻는다. 센서 접근 가능 여부와 측정 오차를 처리해야 한다.
- 플랫폼 권한, 지원 OS 버전, 운전자 주의 분산 가이드라인은 구현 시점의 공식 문서로 다시 확인한다.

### 랠리 스타일 HUD 정보 구성 (예시)

```
MIXNAVUTS / NAV HUD                         GUIDANCE ACTIVE
CURRENT SPEED   72 km/h      LIMIT 80 km/h
NEXT MANEUVER   350 m  우측 진출로
ROAD AHEAD      우측 굽은 구간 · 방향 안내
ETA             14:36
```

랠리 스타일의 시각 요소를 일반 도로의 합법적인 주행 안내에 적용한다. 페이스노트식 "ROAD AHEAD"는 도로 형상(굴곡도)에서 바로 만들 수 있다. 엔진은 이미 링크별 굴곡도를 가지고 있다.

## Distribution 모듈에 대한 주의

다수 차량의 경로 분배는 사용자 점유율이 충분히 높아야 효과가 있다. 점유율이 낮으면 영향이 거의 없다. 반대로 높아지면 모두를 같은 우회로로 보내 그 길을 막는 진동(flapping)이 생긴다. 사용자 규모와 자체 주행 데이터가 생긴 뒤에 시작하는 것이 맞다.
